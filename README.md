# 梯田秋收机械协同

协调梯田收割、山地单轨转运、连续烘干与安全入库的设备与粮食批次，覆盖沿河山区集中收割期多社共用设备的排产、中断、改派与恢复。

## 领域资料

`contracts/domain.schema.json` 记录共享资料结构，`fixtures/domain.json` 是不含真实个人信息的示例。参与方包括农机中心调度员、种植合作社、设备操作人员、粮食品质人员。

当前资料依据以下业务事实维护：

- 当地使用山地单轨运输车解决梯田运粮困难
- 秋收期间调配六十余台联合收割机并包含外省设备
- 稻谷需连续烘干并把水分控制在安全储存标准内

## 协同服务

服务内核（`src/`）是一个事件溯源 + 事务调度模型，零外部依赖：

| 模块 | 职责 |
| --- | --- |
| `state.js` | 纯函数事件重放：地块、设备、预约、批次、队列、故障、延期 |
| `store.js` | JSONL 事务日志，一个事务恰好一行；残行在重启时截断，事务不留半份 |
| `intervals.js` | 区间合并、最早空闲段、每日班次窗口 |
| `planner.js` | 收割机班次/坡度、单轨区段载重与互斥、烘干仓容量与连续处理时长、最晚完成时间 |
| `service.js` | 全部协同命令、角色鉴权、FIFO 裁决、中断/恢复、改派、时间推进 |
| `queries.js` | 批次追踪、延期影响、安全储存报告、设备看板 |

### 关键规则

- **地块登记**：成熟度、坡度、预计产量、可达收割设备、最晚完成时间；合作社只能确认自己的地块。
- **交接链原子建立**：收割 → 单轨分趟转运 → 连续烘干在同一事务内建立，批次自建立起就有明确烘干去向；约束预检失败不产生任何预约。
- **共享资源约束**：收割机按每日班次排产且受坡度上限限制；单轨区段互斥运行并校验单趟载重；烘干仓独占、容量受限，烘干必须一次连续完成。
- **FIFO 裁决**：每台设备一条队列，队首先得最早可行时段；自身条件不满足（超重、不可达、等待复测）的预约标记阻断并留队，后续预约可越过。
- **按序追加的现场事件**：实际称重只增删尚未装载的趟次；设备停机立即隔离并打断在执行作业（保留剩余工时）；降雨停工只影响田间与单轨；跨村调机占用运输窗口；入仓水分复测重算烘干时长。
- **临时改派**：只允许释放尚未开始的资源；已经装载的粮食拒绝改派，必须沿交接链到达原定烘干仓。
- **连续烘干中断**：整批作废重做，须粮食品质人员独立复测水分后才能重新开烘；入库复测超标只记录结论、禁止入库，可由调度员安排返烘。
- **角色边界**：合作社只能操作自己的地块与批次，调度员处理全局冲突与改派，质检人员独立记录入仓/入库水分，操作人员上报称重、故障与降雨。
- **重启恢复**：重放日志即可继续：到期作业开工、故障保持隔离、排队顺序保持不变。

### 查询接口

- `traceBatch(state, batchId)`：批次当前位置、明确去向、下一台设备与计划时间、完整交接链。
- `delayImpact(state)`：延期影响了哪些地块、原因序列、当前计划是否仍晚于最晚完成时间。
- `storageReport(state)`：每批稻谷的入仓/入库水分与是否达到安全储存标准（≤13.5%）。
- `equipmentBoard(state)`：每台设备当前占用与 FIFO 队列。

## 开发命令

- 运行测试：`npm test`
- 语法检查：`npm run build`
- 端到端演示：`npm run demo`

上述命令只读写仓库内文件与 `/tmp` 下的临时日志，不连接外部业务服务。
